Plug & Produce and Multiagent

CMAS

CMAS is a framework for Plug & Produce that makes it possible to use configurations rather than programming to model and handle parts in a manufacturing system. The key tasks are to define goals for parts. Goals are central in the design of autonomous multi-agent systems. The final goal for a part is to become manufactured and this can be divided into several subgoals. A goal can achieve its completion by requiesting skills from available resources. Therefore, the task of defining skills for resources is important. Typically, a resource skill is established upon resource acquisition and tends to remain relatively constant throughout the resource's lifespan. It's worth noting that a skill might demand additional control logic to function effectively, hence, it is possible to develop more conventional programs for skill execution as well. Typically, before the first deployment the system integrators will carrying out the definition of low-level skills.

Goal-oriented multi-agent control is one approach to handle flexible and reconfigurable manufacturing systems. Goals are important to be able to create autonomous agents. An autonomous agent must have the possibility to decide not only how to achieve a goal, but also which goal to select. For parts that will be manufactured, a state-oriented model is adopted implying that each agent associated with a part tries to reach a final state by executing all assigned goals. When all goals are finalized, the part is ready. A part is defined as a part of a product or the product itself that will be manufactured within the boundary of the actual manufacturing system. Hence, a goal can only be fulfilled by utilizing skills on resources within this boundary. To assist part-agents to reach their goals, process plans exist that defines skills needed to reach a specific goal. Process plans can be define without specifying resources, only required skills, requirements, and abstract interfaces are specified. Abstract interfaces are connected to a resource-agent when needed during runtime, the resource-agent are selected after a negotiation process. Hence, the process plans of goals separate the resources from the goals. This makes it possible to have several potential solutions in the system for the autonomous agents to select the most suitable process plans. A goal depicts the future desired state of the system. However, the sequence of goals is important, methods to configure and execute concurrent and parallel sequence of goals. Plug & Produce systems, controlled by CMAS, enables the possibility to rapidly plug in and out resources to adapt to the actual manufacturing situation. Resources prepared with suitable skills and process plans can be plugged in without doing any software reconfiguration of the CMAS. Parallel goals can utilize resources concurrently in parallel. If only one resource is available, goals that are configured to execute in parallel will be executed in sequence instead by the single resource. This approach enables the possibility to rapidly avoid bottlenecks in the production that can appear due to for example changed customer orders just by plugging in suitable resources. No reprogramming or software reconfiguration is needed in these situations.

Overview of CMAS execution model

The CMAS execution model separates what should be achieved from how it is executed.
Instead of programming specific machines or robots directly, programs describe goals and required capabilities. The system then determines how to achieve them using the available resources.

This allows programs to remain independent of specific hardware while the system dynamically allocates suitable resources.

The main concepts of the CMAS execution model are:

  • Goals
  • Skills
  • Interfaces
  • Resources
  • Planner Agent

Goals

A Goal represents a desired state or result that should be achieved in the system.

A goal does not describe how the task should be executed. Instead, it defines what outcome is required. The Planner Agent is responsible for determining how the goal can be achieved using the available skills and resources. Goals are used on Part Agents.

Skills

A Skill represents an executable operation provided by a resource agent.
Examples of skills could be:

  • Move
  • Pick
  • Place
  • Weld
  • Inspect

Skills are typically implemented by agents representing machines, robots, or software components in the system.

Interfaces

Interfaces define the capabilities that a resource exposes to the system.
Agents interact with interfaces rather than directly with specific resources.

Abstract interfaces allow the system to dynamically find a suitable resource that provides the required skills.

Example:

abstract Robot : interface;
Robot.Pick();
Robot.Place();

The program does not specify which robot should perform the task.
Instead, the system selects a compatible resource during runtime.

Resources

Resources are agents representing physical or logical entities that provide skills in the system.

Examples include:

  • Robots
  • Machines
  • Conveyors
  • Software agents

Each resource exposes one or more interfaces that describe the skills and variables it provides.

Planner Agent

The Planner Agent coordinates the execution of goals and skills.

Its responsibilities include:

  • Finding compatible resources for abstract interfaces
  • Negotiating and binding interfaces to resources
  • Generating execution plans
  • Optimizing resource usage based on cost or availability

By combining goals, skills, and interfaces, the Planner Agent can automatically determine how a task should be executed within the system.

Summary

The CMAS execution model allows developers to focus on describing the required operations rather than controlling specific hardware.

Programs define goals and call skills through interfaces, while the system automatically handles:

  • resource selection
  • execution sequencing
  • negotiation
  • runtime adaptability

This approach enables flexible automation systems and supports Plug & Produce environments where resources can be added or removed during runtime.
