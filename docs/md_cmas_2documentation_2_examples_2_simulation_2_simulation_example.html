examplesimulation_page Crane Simulation Example

Introduction

Start the crane simulation program, it should look like the picture below. Within the simulation, there's a crane capable of motions along the x y plane. Equipped with a vacuum gripper, the crane can affix products to itself and move them around. Within the simulation model, there exist two sources: source 1 for part A and source 2 for part B. Additionally, two processes are available for part processing. Upon completion, a product can be released into the sink for removal from the system.

The crane simulation software.

The manufacturing environment includes some sensors and control point signals that can be reach through MODBUS TCP.

Table of MODBUS signals
Name Type Direction Address Explanation
setX Integer Write 1 crane set value for x
setY Integer Write 2 crane set value for y
vacuum Boolean Write 3 Crane lift mechanism Vacuum on/off
startp1 Boolean Write 4 Start signal to process 1
startp2 Boolean Write 5 Start signal to process 2
atX Integer Read 15 Crane current position in x
atY Integer Read 16 Crane current position in y
source1 Boolean Read 17 Proximity sensor in source 1
source2 Boolean Read 18 Proximity sensor in source 2
p1running Boolean Read 19 True if process 1 is running
p2running Boolean Read 20 True if process 2 is running
p1sensor Boolean Read 21 Proximity sensor in process 1
p2sensor Boolean Read 22 Proximity sensor in process 2
button1 Boolean Read 23 Button 1 state
button2 Boolean Read 24 Button 2 state

Modelling

Create Parts

In this step we will create the two parts ProductA and ProductB. To better organise the project start by adding a new folder to the modelling tree and rename it to Products. Select the folder and enable the property MakeInstances.

\Note If MakeInstances is false the entity inside that folder will not be instantiated during run.

Inside that folder create two Part agents and name them ProductA and ProductB. For each product set AutoDeploy to false to make sure that products are not deployed automatically.

Interface

Open the Interfaces folder and create a new Interface for each part and name it InterfacePart. This interface is to make sure that we can interact with resources.

Create template variable

Create a new folder in the modelling root and name it #Templates# make suer that #MakeInstances# is #false#. Inside #Templates# add a new VariableObject and name it #Location#. This will be used as a base for any location in the system. Open the folder #Location# and inside #Items# create two new #VariableInteger# and name them x and y.

Create Sources

Now create a new folder named Resources and enable MakeInstances. Inside that folder create a new Resource agent and name it Source1. We want to make use of the sensor to automatically create a new product agent when a product enters the source. The first step is to make sure that Source can host a product by creating a new InterfaceSpecialisation named InterfacePart. To be able to use the interface as a location change the property SpecialisationName to Location. Now we need a location, drag the template variable Location from the Template folder to the new interface folder called Specialisation and select Copy.

Note
It is also possible to manually create the VariableObject but it can be more convenient to work with templates. If you select Reference instead of Copy a reference is made, if you then change the template all referenced objects will be updated accordingly.

We also need to create two specialisation skills. Create a new Skill inside the Skills folder, name it pick and change the PostAction to DETACH. Also create a Skill named place with PostAction set to ATTACH. These skills can be used by the internal AI planner or by other resources to be attached or detached from the source.

The second step is to add sensor1 as a variable to Source1. Inside the Variables folder on Source1 create a new VariableBoolean and name it sensor1. Select the new variable sensor1 and set the source to modbus.tcp: and change the address to 17. The sensor1 variable is now connected via MODBUS to source1 inside the simulation. Set ReadOnly to true since the sensor is an input signal and it is not possible to write to it. Now we need to write the logic for the sensor. Open Actions editor for Source1 and write the following program.

Source1 Action

program Source1;
var sensor1OldValue:boolean;
procedure Deploy(Name:string);
begin
if not deployandattach(Name) then
error 'Unable to attach ' + agent.Name +' to ' + Name;
end.
procedure Running;
begin
// Based on the state of the sensor create a new part agent
// the new part will be attached to us via a compartible interface (InterfacePart)
if agent.sensor1 AND not sensor1OldValue then
begin
Deploy('ProductA');
end;
sensor1OldValue:=agent.sensor1;
end.
// Constructor, create a new part agent during startup if sensor is true
begin
sensor1OldValue:=agent.sensor1;
if sensor1OldValue then Deploy('ProductA');
end.


Create Crane

Inside the Resources folder create a new Resource agent named Crane. Add four VariableInteger in the Variables folder and map them to setX, setY, atX and atY according to the modbus table. By setting atX and atY we can make the crane move and by reading atX and atY we can see the current position. To be able to control the crane we need to create two new VariableInteger named targetX and targetY (they will only be used internally in the agent). Now we need to write the logic for the Crane controller. Open the Actions editor for Crane and write the following program.

Crane Action

program Crane;
var oldx:=-1, oldy:=-1:integer;
// Main controller for the crane motion
procedure running;
begin
if oldx<>agent.targetX then begin
agent.setX:=agent.targetX;
oldx:=agent.targetX;
end;
if oldy<>agent.targetY then begin
agent.setY:=agent.targetY;
oldy:=agent.targetY;
end;
end.
// Constructor
begin
agent.targetX:=agent.atX;
agent.targetY:=agent.atY;
oldx:=agent.targetX;
oldy:=agent.targetY;
end.

Test run

It should now be possible to test the model by pressing run in CMAS. The runtime three should look like this.

The runtime tree.

In the runtime tree expand the Crane and the Variables folder and select the targetX variable. In the Properties window you should see a valuem current position of the Crane (crane default position at start is 500). Change the value to 300 and press the [TAB] key. The crane should now start to move to 300 in the x direction. You can also test to create a new Product by pressing the [generate] button inside Source1 in the simulation. Inside CMAS a new part agent ProductA should be deployed according to the logic of the Source1. The product will be finished immediately and transfered to the Finished folder since it has no goals yet.
